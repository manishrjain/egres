# The whole benchmark, in the order `./run.sh suite` runs it. One step
# per line: a label, the test (a script here, without .sh), then
# VAR=value settings and the test's arguments. BACKEND picks the
# platform (vm, egres, pgshared). Each script's header says what the
# settings mean. Edit to change a run; the copy used is saved with its
# results.

drive-idle            drive_idle

# 1. Isolation: a heavy tenant beside quiet ones. pgshared, every
# tenant a database in one stock Postgres, is Egres's shape without
# its metering. To 512 heavy (2,048 writing connections on the box's
# 28 threads): on a datacenter drive none of the sides had broken at
# 64, so the count goes on until the quiet tenants' tail gives.
noisy-vm        noisy  BACKEND=vm       HEAVY=0,1,2,4,8,16,32,64,128,256,512
noisy-egres     noisy  BACKEND=egres    HEAVY=0,1,2,4,8,16,32,64,128,256,512
noisy-pgshared  noisy  BACKEND=pgshared HEAVY=0,1,2,4,8,16,32,64,128,256,512

# 2. What a tenant costs, and how many fit. A micro-VM holds about
# 96 MiB settled (tanland), so 600 fills a 64 GiB budget and 1,000 a
# 100 GiB one; the count stops early where it does not fit.
footprint-vm          footprint  BACKEND=vm      1 10 100 300 600 1000
footprint-pgshared    footprint  BACKEND=pgshared 100 1000 10000
footprint-egres       footprint  BACKEND=egres   1000 10000 50000 100000

# 3. Agents onboarding and working, the micro-VMs put to sleep and woken
# as memory runs out, restored from a snapshot: how a micro-VM
# platform wakes a tenant. (WAKE=boot, a fresh boot instead, is a
# check, not a step: both ran out of memory at the same count.) At
# 30 onboardings a second both sides ran out of onboarding speed before
# memory or latency gave out (tanland); 10 lets those show.
agents-vm             agents     BACKEND=vm      WAKE=restore ONBOARD=10
agents-egres          agents     BACKEND=egres   ONBOARD=10
