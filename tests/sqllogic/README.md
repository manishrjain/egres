# Postgres conformance

Postgres's own regression files, replayed against egres with a real
Postgres as the oracle. Records are compared one by one, in
sqllogictest's form, so one unsupported statement does not desync the
rest of a file.

- `pg/`: unmodified copies of `src/test/regress/sql/*.sql` from the
  PostgreSQL 18.6 source tarball. `test_setup.sql` supplies the shared
  tables (`INT8_TBL` ...) the others expect pg_regress to have made.
- `<name>.slt`: generated by `convert.py`, which runs each statement
  against Postgres and records its outcome. Format in `slt.py`.
- `<name>.skips`: records egres does not support yet, with its error.
  Written by `run.py --write-skips`; do not edit.
- `<name>.accepted`: hand-written, the divergences egres means, one per
  line: `<index>\t<first line>\t<reason>`.

## Run

    scripts/sqllogic_e2e.sh                # zig-out/bin/egres on 3210
    scripts/sqllogic_e2e.sh --write-skips  # refresh skips after a fix

Each record lands in one bin: passed; unsupported (egres errored where
Postgres succeeded); blocked (failed only through an earlier failure:
its table is missing, its transaction aborted, or an earlier write left
its rows unlike Postgres's); diverged (different results, or egres
accepted a statement Postgres rejects). Errors compare as failure
versus success, never by text. The run fails on unsupported records
not in skips, divergences not accepted, and a lost connection.

## Regenerate

`convert.py` wants a Postgres 18 on port 5433. The C locale matters:
text then sorts bytewise, as in egres.

    docker run -d --name pg18-oracle -p 127.0.0.1:5433:5432 \
        -e POSTGRES_HOST_AUTH_METHOD=trust \
        -e POSTGRES_INITDB_ARGS="--locale=C --encoding=UTF8" \
        postgres:18.6
    /tmp/zdb/psycopg-venv/bin/python tests/sqllogic/convert.py \
        tests/sqllogic/pg/int8.sql

Regenerating can shift record indexes: rerun with `--write-skips`, and
fix the `.accepted` entries the run reports as stale.
